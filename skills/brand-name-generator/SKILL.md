# Brand Name Generator

ブランド戦略を、比較して選べる名称へ翻訳する。対象は新規命名、改名、候補評価、既存案の絞り込み。戦略を作る依頼やロゴ制作とは区別し、依頼された範囲を完了する。ユーザーの指定言語で応答する。特定モデル、外部エージェント、専用サービスは必須ではない。

本スキルの指示と次の必要な参照を全文取得できたか確認し、取得できない部分を記憶や要約で代用しない。

| 読む時点・条件 | 参照と用途 |
|---|---|
| 最初に読む。評価・調査・納品で必須 | [screening.md](references/screening.md)：名前だけの審査、言語・使用条件の確認、証拠の残し方 |
| 候補生成前に必須 | [language-policy.md](references/language-policy.md)：名称の構成言語、応答言語、評価言語の決定 |
| 文化・ファッション・ホスピタリティ・編集媒体の洗練が必要、または凡庸とのフィードバックがある | [editorial-character.md](references/editorial-character.md)：参照調査、却下と改訂、実際の使用形の比較 |
| 手法の出典や改変を確認するとき | [sources.md](references/sources.md)：原典、適応内容、ライセンスと適用範囲 |

## 戦略から受け取るもの

完成済みのブランドホロタイプ、または同じ内容を持つ戦略文書の本文を使う。名前だけ、以前の会話の存在、戦略のファイル名は入力の代わりにならない。入力の版・日付・対象・根拠・決定状況を記録し、以下の8要素を対応づける。

| 戦略の要素 | 命名へ引き継ぐ判断 |
|---|---|
| Purpose | ブランドが外に対して果たす役割。大きな理念をすべて名前に詰め込まない |
| Market / Competitor | 顧客が選ぶ代替手段と既存名称。混同を避ける相手と、必要なカテゴリー理解 |
| Target Consumer | 誰が、いつ、どこで読み、聞き、検索し、誰かに伝えるか。購入者と利用者が違えば双方 |
| Benefit | 顧客が得る価値。名前が示唆すべき価値と、説明文に任せる内容 |
| Function / Performance | 価値を実現できる能力と証拠。名前による誇大な品質・効果の約束を避ける境界 |
| Equity | すでに顧客にある連想。改名時に失うもの、残すべき呼称・音・意味 |
| Personality | 関係性にふさわしい語り方、距離感、振る舞い。形容詞をそのまま名詞化しない |
| Icons | 継続すべき識別資産、文字・音・既存表記との関係。新案を確立した資産と呼ばない |

目的、成長源、現在の選択・認識、戦略の理由、資源や制約、未確定の前提も受け取る。8要素は8個の単語材料ではなく、互いに矛盾しない判断の条件である。命名しやすさのために対象顧客、便益、能力、人格を変更しない。

十分な戦略があれば再作成しない。欠落が判断に影響する場合は、その箇所だけ補う。戦略そのものがない場合は、利用可能な `brand-holotype` の全指示と必須資料を読み、戦略を先に作る。公開版では [RPSTR9の完全な戦略メソッド](https://raw.githubusercontent.com/rpstr9/rpstr9-marketing-library/main/MARKETER.md) のBrand Holotype能力と割り当てられた全文資料を使う。取得できなければ、既存戦略の本文を依頼する。ユーザーが探索だけを求めた場合は仮説を明記して進められるが、完成した戦略に基づく最終推奨とは呼ばない。

命名は戦略の独立した下流分岐であり、Perception Flow、広告計画、ビジュアルアイデンティティの完成を前提にしない。既存のそれらが名称の使用条件を示すなら利用する。新しい戦略概念に変更が必要なら上流へ戻し、利用可能なConcept Reviewの全手順を適用する。名称の局所修正で無関係な戦略全体をやり直さない。

## 命名ブリーフを定める

会話・資料からまず埋め、調査できず、仮定にすると方向が変わる事項だけを簡潔に尋ねる。項目を埋めるための長い質問票にしない。

- 命名対象と階層：企業、ブランド、商品、サービス、媒体、アカウントのどれか。既存の親ブランドとの関係。
- 新規か改名か。改名では維持案も比較し、既存顧客の認識、検索や紹介、移行の負担を含める。
- 対象市場・言語、実際の使用場面、将来の拡張範囲とその確度。
- 顧客に伝わってほしいこと、誤解されてはいけないこと、既存資産、避ける名称と却下理由。
- 表記、読み、長さ、禁止語、必須語、期限などの拘束条件と、変更可能な好みを分ける。
- 表示名、アカウントID、ドメイン、商号、商標を別項目にする。必要なプラットフォーム・ドメイン・国・商品役務、取得予算が不明なら不明とする。

名称がその場で担う役割と、説明文・プロフィール・既存ブランドが補う役割を決める。すべてを名前だけで説明させない。一方、由来を長く説明しないと意味を持てない案は、その負担を評価に含める。

## 名称をつくる言語と評価する言語を分ける

候補生成前に [language-policy.md](references/language-policy.md) を読み、命名ブリーフに「名称の構成言語」「応答言語」「評価する市場・言語」を別々に記録する。名称の構成言語は、今回の明示的な指定、ユーザーが設定したローカル既定値の順で決める。既定値が未設定なら、資料にある明示的な命名条件から決め、方向を左右する曖昧さだけを確認する。会話が日本語であること、日本市場や日本人を対象にすること、カタカナ読みが必要であることだけで構成言語を日本語に変更しない。

英語を構成言語にした場合は、英語の既存語、英語の語根・複合・比喩・英語由来の造語から候補をつくる。日本語の形態素、日本語の語をローマ字にしたもの、かなの語呂合わせを素材にしない。既存の英語語彙は歴史的な外来語源だけを理由に除外しない。日本語名や他言語名を明示的に求められた場合は、その指定を優先し、構成言語と採用理由を記録する。

日本語・カタカナは、候補の発音、拍とリズム、聞き取り、入力、意味のリスク、使用場面への適合を評価するために使う。カタカナ化から新しい日本語の語根や後付けの日本語語源を発明しない。評価で弱点が見つかったら、選んだ構成言語内で候補を修正する。構成言語を変える必要があるなら、その判断を明示してブリーフへ戻す。

文化・ファッション・ホスピタリティ・編集媒体の洗練が求められる場合、または名称が凡庸とのフィードバックがある場合は、[文化的な個性と実物比較](references/editorial-character.md) を全文読み、参照調査、却下、改訂、実際の使用形の比較に適用する。既存の戦略・言語・調査手順を置き換えない。

## 異なる考え方で候補をつくる

戦略上の価値から複数の意味の方向を立て、それぞれの期待する連想とリスクを示す。意味の方向と語の作り方を区別する。同じ語尾や語根の変更だけを別方向として扱わない。

説明的な表現、価値をほのめかす表現、比喩、既存語の意外な転用、複合語、造語などを、課題に合うものから使う。人名や略語も条件が合えば検討する。特定方式を常に優位としない。語源や外国語の意味を採用理由にするなら辞書などで確かめ、創作した由来と実在の意味を区別する。

初期発想と比較を分ける。候補数は必要な幅、制約、重複、追加探索の価値に応じて調整する。大量生成したふりをしない。強い候補が足りなければ、似た案を足さず、別の意味の方向へ戻る。似た音・綴り・発想を束ね、少数の代表を残す。探索済み方向と主要な却下理由を保存し、不要な全候補の羅列は避ける。

候補や既存ブランドの実例から、語根、業種、作風、名称、語尾を恒久的な既定値にしない。前回の好みも、今回に適用するとユーザーが示した範囲でのみ継承する。

## 比較し、使用条件を調べる

必須条件への違反、混同の強い兆候、能力と矛盾する約束を先に分ける。創造性の点数で重大な欠陥を相殺しない。続いてscreening.mdの「名前だけの品位・語感の審査」を行い、ブリーフの信頼感や距離感に合わない案を却下・保留する。由来説明、短さ、読みやすさ、空きそうなIDでこの判断を相殺しない。残った候補を同じ使用場面で比較し、screening.mdに従って次を確認する。

1. 戦略とのつながり、初見の意味、カテゴリーとの適切な距離。
2. 思い出す手がかり、読み・聞き取り・入力の負担、他案との区別。
3. 日本語の読みと表記、対象言語・文化、誤読・同音・略称の問題。
4. 既存名称の使用、必要なハンドル・ドメイン、対象国の商品役務に関する予備的商標調査。
5. 将来の使い道と、意味を定着させる負担。拡張を無限に仮定しない。

SMILE / SCRATCHはAlexandra Watkinsによる発想・評価の視点として使う。ブランドに必要な意味の示唆、記憶の手がかり、イメージ、表現の広がり、感情とのつながりを検討し、綴りの難しさ、模倣、過度の限定、無理な言葉遊び、凡庸さ、内輪の知識、発音の難しさを点検する。説明的な名称が有利な用途もあるため、普遍的な合否検査にしない。結果は理由のある判断であり、顧客の反応の観測ではない。

総合点の細かな差で順位を正当化しない。重要基準ごとの長所、弱点、判断を変える条件を示す。数値比較が必要なら尺度と重みの理由を先に定め、未確認をゼロ点や合格に置き換えない。文字や音に固定的な性格、記憶効果、購入効果を割り当てない。

## 選べる形で届ける

依頼に合う量の候補を、推薦理由が比較できる形で示す。通常は少数の有力案と必要な代替案で十分。ユーザーが指定した数や探索範囲を優先し、弱い案で枠を埋めない。

成果物 `naming` に次を保存する。人が読める文書でよく、技術的なスキーマ入力を要求しない。

- 対象・版・日付・使用言語、元の戦略本文または同梱された参照先と版、依頼範囲、ブリーフ、前提。
- 候補比較表：正式な表示案、読み、意味の方向、名前だけでの語感・品位の判断と却下／保留理由、戦略的理由、主な弱点、確認状況。
- 各有力案の実際の使用形：表示名、必要な別表記・読み、ハンドル案、ドメイン案。未調査の綴りは提案として示す。
- 検索した対象、クエリ、情報源、日時、範囲、観測結果と未確認事項。省略した調査も明記。
- 第一推奨と代替案、その理由、残る条件、選ばなかった方向の理由。推奨・ユーザー選択・権利確認・取得済みを区別。
- 必要なら、対象者に何をどう確かめ、どんな結果で判断を変えるか。実施前の計画と実測値を混ぜない。
- 次に必要な判断・調査と、アイデンティティやプロフィール制作に渡す表記、読み、意味、保護すべき条件。 引継ぎでは名称が仮称／推奨／選定済みのどれか、構成言語、調査範囲、残した候補と却下理由を明示する。仮称だけのIdentity画像を命名実行済みの証拠にしない。

第一推奨を黙って正式名称として確定しない。選択が明示されていなければ「推奨」、ユーザーが選定まで委任したなら「委任に基づく選定」と記録する。選定しても権利確認や取得を済ませたことにはならない。購入、出願、登録、既存アカウント改名、公開は命名の依頼だけでは実行しない。

フィードバックでは、嫌いな単語だけでなく、意味の方向、音、理解の負担、戦略の不一致のどこが問題かを整理して修正する。変わっていない入力と確認結果を再利用し、期限や対象が変わった可用性だけ再確認する。名称の変更が関係する資産へ影響を伝え、無関係な戦略やFlowを変更しない。

## 最終確認と改訂

1. **入力と候補を照合する。** 素材は記録した構成言語と合うか。評価用の日本語を生成素材や創作語源にしていないか。8要素を勝手に変えていないか。候補は意味でも異なるか。表記と読みは対応するか。
2. **名前だけで審査し、弱点を直す。** screening.mdの審査を、由来や使用形の説明による救済なしで行う。重大な欠陥やブリーフとの不一致があれば、その案を却下するか、意味の方向・音・構成を修正して1と2を再確認する。説明文だけの修正で合格にしない。有力案が残らなければ、不足する方向と条件を示して探索へ戻る。
3. **根拠と使用条件を確認する。** 由来を創作事実にしていないか。検索対象・日時・範囲と未確認が見えるか。検索なしの空き判定や商標保証がないか。調査ツールが使えなければ、実行できた比較と未実施の調査を区別し、必要な確認を引き継ぐ。
4. **選べる成果物を確認する。** 具体的な推奨、その理由、残る条件と次の行動まで届いているか。推奨、選定、権利確認、取得済みを区別する。
5. **変更部分を再確認する。** 調査やフィードバックで案を変えたら、影響する1〜4を再実行してから届ける。変わっていない入力・有効な確認結果は再利用し、未解決の不足は明示する。無関係な戦略やFlowへ修正を広げない。
